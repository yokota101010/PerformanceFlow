# Feature Specification: Domain Model & CRUD Matrix Alignment

**Feature Branch**: `012-domain-crud-alignment`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "domain-model.md と crud-matrix.md の変更に合わせて機能を改修してください。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 15ドメイン集約に基づく単一集約整合性操作 (Priority: P1)

業務ユーザーおよび管理者は、新しく定義された 15 ドメイン集約（プロジェクト、案件、発注、月別案件社員工数、社員、発注先、要員、社員単価、要員単価、その他経費、四半期区分等）の境界を遵守したデータの入力・編集・削除を行いたい。特定の集約（例: 案件集約）の変更操作において、他の集約のデータが不正に直接書き換えられず、単一トランザクションでの整合性が保たれること。

**Why this priority**: システム開発憲法およびデータモデル正本が定める最重要原則「単一トランザクション・単一集約」を機能全体で保証し、不整合バグを完全に排除するため。

**Independent Test**: 各 Command 画面（F01〜F11）においてデータ更新を行った際、自集約のリポジトリのみに変更が適用され、他集約のストアへ直接書き込みが行われないことを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーが「案件管理（F05）」画面で案件および案件明細の追加・更新を行うとき, **When** 保存を実行したとき, **Then** 案件集約（`案件` および `案件明細`）のみが永続化され、プロジェクト集約や発注先集約などは読取参照のみで状態変更されないこと。
2. **Given** ユーザーが「社員マスタ管理（F02）」や「要員マスタ管理（F04）」でマスタデータを更新するとき, **When** 保存を実行したとき, **Then** 該当マスタ集約のドメインオブジェクトの制約検証（単価や所属のバリデーション）が通過した場合にのみ単一集約として永続化されること。

---

### User Story 2 - 単価設定および四半期区分管理機能の適用 (Priority: P2)

管理者は、「社員単価設定（F08）」「要員単価設定（F09）」「四半期区分設定（F11）」画面を通じて、社員や要員の月別単価履歴および会計年度の四半期区分の変更を行い、原価および業績算出の基準データを正確に管理したい。

**Why this priority**: 原価計算（月別案件明細原価）および業績集計（四半期別案件明細業績）の正確な算出に必要なマスタ/単価集約データを独立して更新・保持可能にするため。

**Independent Test**: 社員単価および要員単価の期間変更、四半期区分の設定を行い、それぞれの集約オブジェクトが独立して作成・更新できることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理者が特定社員の月別単価を「社員単価設定（F08）」画面で入力したとき, **When** 保存したとき, **Then** `社員単価` 集約ルートと `月別社員単価` メンバーが同一集約境界として永続化されること。
2. **Given** 管理者が四半期（例: Q1, Q2）の開始月・終了月を「四半期区分設定（F11）」画面で変更したとき, **When** 保存したとき, **Then** `四半期区分` 集約が更新され、関連するクエリ表示で新たな四半期基準が適用されること。

---

### User Story 3 - 参照画面におけるプル型オンデマンド算出 (Priority: P3)

経営者および管理者は、「業績・収支サマリ表示（F12）」「社員別工数サマリ表示（F13）」「要員別工数サマリ表示（F14）」などの参照画面を閲覧する際、入力済みの一次データから動的かつ即座に最新の原価・業績サマリがオンデマンド算出され、常に整合した最新数値を把握できること。

**Why this priority**: 一次データの更新時にサマリを即時バッチ同期しない「結果整合性（プル型同期）」を実現し、表示クエリ起動時に常に正確な結果を得られるようにするため。

**Independent Test**: 一次データ（工数や単価）変更後に参照専用画面を開いた際、自動的にオンデマンド再計算が走り、最新の計算結果が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーが「工数入力（F07）」で当月の工数を変更した後, **When** 「業績・収支サマリ表示（F12）」画面を開いたとき, **Then** 最新の工数と単価集約からオンデマンドで `月別案件明細原価` および `四半期別案件明細業績` が再計算されて画面に表示されること。

---

### Edge Cases

- 関連する社員単価や要員単価が設定されていない年月に対して工数入力や原価算出が行われた場合、単価ゼロまたは未設定警告として扱われシステムクラッシュしないこと。
- 月次確定済みの年月に対して一次データ（工数・経費）の追加・変更が試みられた場合、ドメイン検証により明確なエラーメッセージが表示されて変更が拒否されること。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、`domain-model.md` に定義された 15 のドメイン集約（`プロジェクト`, `案件`, `発注`, `月別案件社員工数`, `社員`, `発注先`, `要員`, `社員単価`, `要員単価`, `その他経費`, `四半期区分`, `月別社員工数サマリ`, `月別要員工数サマリ`, `月別案件明細原価`, `四半期別案件明細業績`）を正本としてデータモデルおよびTypeScriptドメインオブジェクトをカプセル化・適用しなければならない。
- **FR-002**: 各 Command 機能（F01〜F11）の永続化処理は、必ず 1 度のトランザクションで単一の集約のみを変更・保存し、他集約へのマルチ更新を行ってはならない。
- **FR-003**: システムは、「社員単価設定（F08）」および「要員単価設定（F09）」機能を提供し、各対象の月別単価履歴を集約境界内で安全に更新できなければならない。
- **FR-004**: システムは、「四半期区分設定（F11）」機能を提供し、会計四半期と対象月度のマッピングを集約として管理できなければならない。
- **FR-005**: 各 Query 機能（F12〜F14）は、表示要求時に一次データ（工数、単価、経費等）からサマリ集約（`月別社員工数サマリ`, `月別要員工数サマリ`, `月別案件明細原価`, `四半期別案件明細業績`）をオンデマンドで算出・再計算して描画しなければならない。
- **FR-006**: すべての集約エンティティは、ドメイン層内部のコンストラクタまたは検証メソッドでビジネスルール（正負制約、FK参照存在、確定済年月制限等）を強制的バリデーションしなければならない。

### Key Entities *(include if feature involves data)*

- **単価集約 (`社員単価` / `要員単価`)**: 対象ID、適用年月、および単価金額を保持する独立した単価履歴集約。
- **四半期区分 (`四半期区分`)**: 年度、四半期名（Q1〜Q4）、および対応する開始・終了年月を管理するマスタ集約。
- **導出サマリ集約 (`月別案件明細原価`, `四半期別案件明細業績` 等)**: 一次データよりオンデマンド算出される読取・分析用モデル。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 15 の全ドメイン集約において、単一トランザクション・単一集約原則を満たす Command 処理のカバー率 100%。
- **SC-002**: 各 Query 参照画面（F12〜F14）でのオンデマンド算出および画面表示が 1 秒以内に完了すること。
- **SC-003**: データ入力時のビジネスルール違反（不正な単価や確定月変更など）に対するドメイン層でのエラー検出率 100%。

## Assumptions

- 既存のブラウザ完結型・LocalStorage 永続化アーキテクチャ（`constitution.md` 準拠）を継続使用する。
- 画面レイアウトおよびコンポーネント構造は既存の設計スタイルに準拠し、追加画面（F08, F09, F11 など）も既存 UI パターンに沿って実装される。
